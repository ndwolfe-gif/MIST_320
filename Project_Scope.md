# Build Me Up – Project Scope Statement
## 1. Project Overview
Build Me Up is a cloud-based Information Systems portal designed for the Architecture, Engineering & Construction (AEC) industry. The system addresses operational bottlenecks caused by miscommunication between job-site field engineers and central office project managers.
The portal replaces paper-based daily logs and unindexed messaging threads with a centralized, real-time system that connects job-site activity, project documentation, change management, safety reporting, and project budget information.
## 2. Project Purpose / Business Need
AEC projects depend on accurate and timely communication between field and office teams. When site logs, blueprint changes, safety incidents, and change requests are stored in separate paper records, emails, or message threads, project managers may not have a current view of project status or financial impact.
Build Me Up will provide a single source of project information so field progress can be compared with project budgets and management decisions can be made using current data.
## 3. Project Objectives
The project will:
- Provide field engineers with a mobile-responsive portal for submitting daily job-site information.
- Centralize daily logs, safety incidents, blueprint modifications, and change requests.
- Give project managers a dashboard for reviewing project activity and approvals.
- Connect approved change orders to project budget information.
- Store project data and files in a secure cloud environment.
- Reduce delays and errors caused by paper records and fragmented communication.
- Improve visibility into project progress, safety, changes, and budget impact.
## 4. Major Deliverables
The project will deliver:
1. A mobile-responsive web portal for field engineers.
2. Daily site log creation and tracking.
3. Safety incident reporting and tracking.
4. Blueprint revision and modification tracking.
5. Change request submission and approval workflow.
6. Change order and budget linking.
7. A centralized project management dashboard.
8. Cloud database and file storage.
9. Role-based user access.
10. Integration capability with existing financial/accounting systems.
## 5. In-Scope
The following functionality is included in the project:
- Mobile-responsive web application for field engineers and project managers.
- Submission and storage of daily job-site logs.
- Uploading photos and supporting files with field records.
- Safety incident reporting and status tracking.
- Blueprint revision and modification tracking.
- Change request submission, review, approval, and rejection.
- Creation or tracking of approved change orders.
- Linking approved change orders to project budget information.
- Dashboard views for project progress, incidents, changes, and financial impact.
- Real-time cloud database access.
- Cloud file storage for project-related documents.
- Role-based access for authorized field and office users.
- Integration with existing enterprise financial/accounting systems.
## 6. Out-of-Scope
- The following items are not included:
- Replacing the organization's enterprise accounting or general ledger system.
- Purchasing or providing tablets, phones, laptops, or other field hardware.
- Physical construction management or control of job-site equipment.
- Payroll processing.
- Human resources management.
- Vendor procurement and purchasing systems.
- Full redesign of existing accounting software.
- Offline-first operation when no internet connection is available.
## 7. Functional Requirements
- The system must allow authorized users to:
- Sign in and access features appropriate to their role.
- Create and submit daily site logs.
- Attach project photos and files to records.
- View previous site logs.
- Report and track safety incidents.
- Upload and track blueprint revisions.
- Flag blueprint modifications for management review.
- Submit project change requests.
- Approve or reject change requests.
- Create or record approved change orders.
- Link change orders to budget information.
- View project progress and financial information on a centralized dashboard.
- Store project records in a cloud database.
- Store project documents in cloud file storage.
- Exchange required financial information with an existing accounting system.
## 8. Non-Functional Requirements
The system should:
- Be accessible through modern desktop and mobile web browsers.
- Use a responsive interface suitable for field use.
- Protect project and financial information from unauthorized access.
- Maintain reliable cloud-based data storage.
- Provide acceptable performance for normal field and office operations.
- Maintain an audit trail for important approvals and project changes.
- Support scalable storage as additional projects and documents are added.
- Present data in a clear and usable format for both field and office personnel.
## 9. Project Stakeholders
Primary stakeholders include:
- Field Engineers – enter daily project information and field changes.
- Project Managers – monitor projects and review requests.
- Safety Personnel – review and track safety-related information.
- Finance/Accounting Personnel – monitor financial impact and accounting integration.
- System Administrators – manage users, permissions, and system configuration.
- Company Leadership / Project Sponsor – evaluate project performance and business value.
## 10. Assumptions
The project assumes:
- Users will have access to internet-connected devices.
- The organization already has an enterprise financial/accounting system.
- Existing financial systems provide an approved integration method or API.
- Users will receive basic training on the portal.
- Project teams will enter information accurately and in a timely manner.
- Cloud hosting and file storage services will be available throughout normal operations.
## 11. Constraints
Project constraints include:
- The solution must remain compatible with existing financial systems.
- The project does not include purchasing new field hardware.
- Access to the portal depends on internet connectivity.
- Security and privacy requirements may restrict who can access project and financial data.
- Integration options may be limited by the capabilities of existing accounting software.
- Development must remain within the approved project schedule and budget.
## 12. Project Boundaries
Build Me Up begins when authorized project users enter or upload field information and ends when that information is stored, reviewed, approved where necessary, and reflected in project-level reporting and budget tracking.
The portal manages project communication and operational information but does not replace the organization's core accounting ledger, procurement process, payroll system, or physical construction equipment.
## 13. High-Level Acceptance Criteria
The project will be considered successful when:
- Field engineers can submit daily site logs from a mobile-responsive interface.
- Safety incidents can be recorded and tracked.
- Blueprint revisions and modifications can be stored and reviewed.
- Change requests can be submitted and approved or rejected.
- Approved changes can be connected to project budget information.
- Project managers can view current project information through a centralized dashboard.
- Project files and records are stored successfully in the cloud.
- Authorized users can access information based on their assigned roles.
- Required project financial data can integrate with the existing accounting environment.
- Core workflows pass functional testing.
## 14. Major Risks
Potential project risks include:
- Poor internet connectivity at construction sites.
- Resistance from users accustomed to paper-based processes.
- Incorrect or incomplete information entered from the field.
- Integration difficulties with existing accounting systems.
- Unauthorized access to sensitive project or financial information.
- Large file uploads affecting performance or storage costs.
- Delays in reviewing or approving change requests.
## 15. Success Measures
Project success can be measured by:
- Reduced reliance on paper site logs.
- Faster communication between field and office teams.
- Reduced time required to review change requests.
- Increased visibility into active safety incidents.
- Improved tracking of blueprint revisions.
- More accurate connection between approved project changes and budget impact.
- Increased availability of current project information to authorized users.
